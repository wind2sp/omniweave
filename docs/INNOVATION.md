# 오메만의 기능 — 벤치마킹 다음 단계

기존 6개 프로그램의 기능을 따라가는 것(구현률, `docs/coverage/`)은 출발선입니다. 오메의 목표는
**프로그램 사이를 오가며 생기는 불편 자체를 없애는 기능**, 그래서 다른 도구가 따라와야 하는 기능입니다.
아래 아이디어는 모두 이미 있는 Loom 엔진(내용 주소 조각, 통합 씬 그래프, 증분 저널) 위에서 만들 수 있게 골랐습니다.

상태: 💡 아이디어 · 🧪 설계 중 · 🚧 구현 중 · ✅ 완료

## 1. 형식 사이의 벽을 없애는 기능

| 기능 | 지금의 불편 | 오메의 방식 | 기반 | 상태 |
|---|---|---|---|---|
| **라이브 개체(Live Thread)** | 같은 로고·표·문단을 포스터·발표자료·보고서에 각각 복사하고, 고칠 때 셋 다 다시 고친다 | 한 개체를 여러 페이지·형식에 *연결*해 배치. 원본을 고치면 모든 곳이 즉시 바뀜 | 내용 주소 노드 공유 | 💡 |
| **한 번 편집, 여러 출구** | 같은 내용을 HWPX(제출용)·PDF(배포용)·PNG(SNS용)로 따로 만든다 | 내보내기 묶음: 한 번에 여러 형식·크기로 출력, 원본이 바뀌면 다시 출력 | 내보내기 파이프라인 | 💡 |
| **문서 ↔ 슬라이드 변환** | 보고서를 발표자료로 옮기며 복사·붙여넣기 수십 번 | 제목·문단 구조로 슬라이드를 자동 분할, 반대로 슬라이드를 A4 유인물로 | 통합 텍스트 모델 | 💡 |
| **원형 보존 왕복(패스스루)** | 다른 형식으로 열었다 저장하면 서식이 깨진다 | 이해하지 못한 원본 조각을 보관했다가 같은 확장자로 내보낼 때 그대로 되돌림 | 조각 단위 저장 | 🧪 |
| **스마트 붙여넣기** | 웹·PDF·워드에서 붙이면 서식이 엉킨다 | 어디서 오든 개체로 변환(표는 표, 이미지는 이미지, 텍스트는 스타일 유지) | 가져오기 모듈 공용화 | 💡 |

## 2. 실수와 사고를 없애는 기능

| 기능 | 지금의 불편 | 오메의 방식 | 기반 | 상태 |
|---|---|---|---|---|
| **시간여행 타임라인** | "최종_진짜최종_v3" 파일이 쌓인다 | 모든 편집 상태가 루트 해시로 남아, 슬라이더로 과거 상태를 보고 그 지점에서 갈래를 만들 수 있음 | O(1) 루트 교체 + 저널 | 💡 |
| **시각 비교(diff)** | 두 버전에서 무엇이 바뀌었는지 눈으로 찾는다 | 화면 타일 해시를 비교해 바뀐 영역만 강조 표시 | Weave key 비교 | 💡 |
| **자가 복구 파일** | 파일 하나가 깨지면 전부 잃는다 | 조각마다 해시 검증, 깨진 조각만 건너뛰고 저널에서 같은 해시 조각을 찾아 복원 | 무결성 검증 ✅ + 저널 | 🧪 |
| **정전·강제 종료 복구** | 저장 안 한 작업이 날아간다 | 바뀐 조각만 수 초마다 기록, 다음 실행 때 복구 제안 | Shuttle 저널 | ✅ |

## 3. 함께 일하는 방식

| 기능 | 오메의 방식 | 기반 | 상태 |
|---|---|---|---|
| **충돌 없는 공동 편집** | 개체·타일 단위 CRDT. 두 사람이 같은 그림의 다른 부분을 칠해도 충돌 없음 | 타일 단위 조각 | 💡 |
| **바뀐 조각만 동기화** | 클라우드·NAS 동기화 시 파일 전체가 아니라 새 조각만 전송 | 내용 주소 | 💡 |
| **검토 모드** | 어떤 형식의 페이지든 같은 방식으로 주석·승인 | 통합 씬 그래프 | 💡 |

## 4. 한국 사용자를 위한 기능

| 기능 | 오메의 방식 | 상태 |
|---|---|---|
| **공문서 서식 검사기** | 기관 제출 HWPX 규격(글꼴·여백·쪽 번호)을 검사하고 한 번에 맞춤 | 💡 |
| **한글 타이포그래피 엔진** | 자소 분리 없는 줄바꿈 ✅, 어절 단위 줄바꿈 ✅, 장평·자간·조판 규칙 | 🚧 |
| **HWPX ↔ DOCX 다리** | 같은 문서를 한글·워드 사용자에게 각각 맞는 형식으로 | 🚧 |

## 우선순위 원칙

1. **매일 겪는 불편부터**: 형식 변환과 복사·붙여넣기 반복을 줄이는 기능(1장)이 먼저.
2. **엔진이 이미 가진 능력을 쓰는 것부터**: 시간여행·시각 비교·자가 복구는 Loom의 해시 구조 덕분에 다른 도구보다 훨씬 싸게 만들 수 있다.
3. **측정하고 말한다**: 기능마다 "전에는 몇 번 클릭/몇 분 → 이제 몇 번"을 재고 README에 적는다.

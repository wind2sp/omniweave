## 4. 정직한 해석

**이 수치가 의미하는 것**

- 각 프로그램에서 사용자가 실제로 찾는 기능 목록(프로그램당 60~100여 개, 사용 빈도 가중)에 대해, 지금 코드가 그 기능을 *제공하는지*의 비율입니다. 판정은 코드를 직접 읽고(근거 파일·함수 기재), Node에서 돌릴 수 있는 것은 테스트로 확인했습니다.
- '구현 가능 상한'은 웹 기술 + Tauri/Rust + Canvas2D→WebGPU 로드맵 안에서 원리적으로 막힌 것(독점 포맷·대형 생성 모델·독점 런타임)을 뺀 천장입니다. 상한과 현재의 차이는 '시간과 인력' 문제이지 아키텍처 문제가 아니라는 뜻입니다.
- 프로그램 간 비교 순서(어느 쪽에 가까운지)는 꽤 믿을 만합니다: 같은 기준과 같은 사람이 판정했습니다.

**이 수치가 의미하지 않는 것**

- *품질·충실도가 아닙니다.* '구현'은 기능이 동작한다는 뜻이지 원본 프로그램만큼 정교하다는 뜻이 아닙니다. 예: 브러시는 '구현'이지만 브러시 엔진 깊이는 Photoshop과 비교할 수 없습니다. 패스파인더는 곡선을 다각형으로 근사하므로 '부분'으로 낮췄습니다.
- *파일 호환률이 아닙니다.* DOCX/HWPX 열기는 '부분'(0.5점)이지만 실제 문서는 표·그림·머리말을 거의 항상 포함하므로, 실사용 문서를 열었을 때 '그대로 보이는' 비율은 이 수치보다 훨씬 낮습니다.
- *기능 목록 자체가 표본입니다.* 각 프로그램의 전체 기능은 수백~수천 개이고, 여기서는 사용자가 자주 쓰는 기능 위주로 골랐습니다. 목록 구성과 가중치에 따라 수치는 ±5%p 정도 움직일 수 있습니다.
- *난이도와 3개월 목표는 추정입니다.* 쉬움 1주·중간 3주·어려움 8주, 3명×12주라는 가정으로 기계적으로 배분한 값이며 인력 계획이 아닙니다. 특히 '글자·문단 단위 서식'처럼 묶음 하나가 실제로는 3주를 크게 넘을 수 있습니다. 예산을 바꿔 보려면 `node scripts/coverage-report.mjs --budget 24`.
- *AI 생성 기능의 '불가'는 '로컬·오픈소스·무료' 전제의 판정입니다.* 외부 생성형 API를 연동하면 기술적으로는 붙일 수 있지만, 비용·개인정보·라이선스 때문에 기본 기능으로 계산하지 않았습니다.

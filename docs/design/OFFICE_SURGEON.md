# Office Surgeon 설계: DOCX·XLSX·HWPX 원본 보존 저장

> 작성: 검수 PC, 2026-11-12, 브랜치 `wip/2026-11-11`. 1단계 범위는 DOCX → XLSX → HWPX입니다. PPTX는 효과 부서가 `pptx.ts`를 마치면 다음 차례로 합니다.
> 원칙은 PSD·PDF Surgeon과 같습니다. **안 고친 것은 원본 바이트 그대로 두고, 고친 부분만 다시 씁니다.**

## 1. 왜 필요한가

지금은 DOCX·XLSX·HWPX를 열어 저장하면 오메 모델에서 문서를 처음부터 다시 만듭니다(`exportDocx`·`exportXlsx`·`exportHwpx`).
그래서 한 글자만 고쳐도 모델에 없는 것이 모두 사라집니다.

- 스타일·테마·글꼴 표
- 머리말·꼬리말·각주
- 이미지·도형·차트
- 구역 설정(용지·여백·단)
- 책갈피·필드·변경 추적·주석
- 사용자 정의 XML·문서 속성

Surgeon은 원본 패키지(ZIP)를 그대로 두고, 바뀐 단락·표·셀만 원본 XML 안에서 갈아 끼웁니다.

## 2. 전체 흐름

```
열기:  bytes ─▶ 기존 가져오기(parseDocxFlow 등) ─▶ 페이지·노드
            └▶ 원본 bytes를 asset으로 보관 + 블록 지도(OfficeSourceMeta)를 page.source.office에
저장:  페이지·노드 ─▶ collectFlow ─▶ 블록 지도와 대조(지문)
            ├─ 모두 그대로      → 원본 bytes 그대로 (바이트 동일)
            ├─ 일부 바뀜        → 바뀐 블록만 다시 쓴 본문 XML + 나머지 ZIP 항목 raw 복사
            └─ 지도를 쓸 수 없음 → 지금처럼 새로 만들기(exportDocx 등) + 알림 한 줄
```

### 새 파일

- `src/io/officesurgeon/zip.ts`: ZIP 중앙 디렉터리를 읽어 항목을 **압축된 그대로(raw)** 복사하고, 바꾼 항목만 새로 압축하는 재작성기.
  - 순서·이름·압축 방식·날짜·추가 필드를 유지합니다. ZIP64와 데이터 서술자를 처리합니다.
- `src/io/officesurgeon/scan.ts`: XML 문자열에서 요소의 **문자 범위**를 찾는 작은 스캐너.
  - 다루는 것: 주석·CDATA·PI·따옴표 안의 `>`·자기 닫힘 태그.
  - DOM에는 위치 정보가 없어서 필요합니다. 요소 순서는 `xml.ts children()`과 같게 셉니다(요소만, 텍스트·주석 제외).
- `src/io/officesurgeon/docx.ts`·`xlsx.ts`·`hwpx.ts`: 형식별 대조와 다시 쓰기.
- `src/io/officesurgeon/index.ts`: 공개 API `officeMeta()`·`saveOfficeSurgical()`·`ENGINE_VERSION`.

### 연결 부분(기존 파일에서 고치는 곳)

- `office.ts`·`xlsx.ts`: 가져오기가 본문의 최상위 요소마다 만든 항목 수를 알려 주는 선택 인자를 추가합니다.
  - 단락 XML을 만드는 함수(`para`·`rPr`·`table`)를 모듈 안 공용 함수로 꺼냅니다. 출력은 그대로입니다.
- `formats/index.ts`: docx·xlsx·hwpx를 열 때 asset과 meta를 붙이고, 저장할 때 Surgeon을 먼저 시도합니다(몇 줄).
- `core/types.ts`: `PageSource.office?: OfficeSourceMeta`와 인터페이스를 파일 끝에 **추가만** 합니다.

## 3. 블록 지도(OfficeSourceMeta)

```ts
interface OfficeSourceMeta {
  engine: number;          // ENGINE_VERSION — 규칙이 바뀌면 지도를 쓰지 않음(새로 만들기로)
  assetId: string;         // 원본 파일 bytes(asset)
  hash: string;            // 원본 내용 해시 — 다르면 쓰지 않음
  part: string;            // 본문 부품 이름 ("word/document.xml", "Contents/section0.xml", "xl/worksheets/sheet1.xml")
  blocks: OfficeBlock[];   // 본문 최상위 요소마다 하나, 원본 순서
}
interface OfficeBlock {
  ids: string[];           // 이 요소가 만든 단락 id·표 노드 id(가져오기 순서). 비면 '내용 없는 블록'(sectPr·책갈피·표 뒤 빈 단락)
  fp: string[];            // ids마다 가져온 직후의 내용 지문
}
```

- HWPX는 구역 파일이 여러 개라 `parts: { part, blocks }[]`로 둡니다. XLSX는 시트마다 하나씩 둡니다(5장).
- 원본 범위(문자 위치)는 저장하지 않습니다. 저장할 때 원본 부품을 다시 스캔해서 얻습니다. 지도가 작고, .omw에 XML이 두 번 들어가지 않습니다.

## 4. DOCX

### 4.1 편집 단위

- **편집 단위는 본문(`w:body`)의 최상위 요소**입니다: `w:p`, `w:tbl`, `w:sdt`, `w:customXml`, `w:bookmarkStart`, `w:sectPr`…
  - 가져오기가 `sdt`·`customXml`·`ins`·`smartTag` 안으로 들어가 여러 단락을 만들면, 그 단락들 모두 한 블록에 속합니다.

### 4.2 지문으로 바뀐 부분 판별

**단락 지문**은 아래 값의 해시입니다.

- 목록 기호를 뺀 글자 조각(`bodyRuns`): 글자·글꼴·크기·굵게·기울임·밑줄·취소선·색·강조·위/아래 첨자·자간.
- 정렬·줄 간격·들여쓰기·왼쪽 여백·단락 뒤 간격·역할(제목·목록).
- 목록 기호 글자를 빼는 이유: 앞의 항목을 지우면 뒤 번호 글자가 바뀌는데, 이것은 편집이 아닙니다.

**표 지문**은 셀(글자·서식·병합·칠)·열 너비·머리글 행·표 글꼴·색의 해시입니다.

- 위치(transform)와 페이지는 넣지 않습니다. 페이지 나눔이 달라져도 바뀐 것이 아닙니다.

### 4.3 저장 알고리즘

1. `collectFlow(pages)`로 지금 항목 순서를 얻습니다. 페이지에 걸쳐 나뉜 표는 다시 하나가 됩니다.
2. 블록마다 그대로인지 봅니다. 아래를 모두 만족하면 "그대로"입니다.
   - ids가 모두 남아 있습니다.
   - 순서대로 붙어 있습니다.
   - 지문이 모두 같습니다.
3. 지금 항목 순서대로 내보냅니다.
   - 그대로인 블록 → **원본 요소 문자열을 그대로** 씁니다.
   - 바뀐 단락 → 원본 단락에서 다시 만듭니다(4.4).
   - 바뀐 표 → 구조(행·열·병합)가 같으면 바뀐 셀만, 다르면 표 전체를 다시 만듭니다(4.5).
   - 새 항목 → 기존 내보내기와 같은 XML로 새로 만듭니다.
   - 지워진 항목 → 쓰지 않습니다.
4. 내용 없는 블록은 원본에서 바로 다음에 있던 내용 블록 앞에 붙어 다닙니다. 그 블록이 지워지면 그다음 블록에 붙습니다.
   - 마지막 `w:sectPr`는 언제나 본문 맨 끝에 둡니다.
5. Word 규칙도 지킵니다.
   - 본문이 표로 끝나거나 표 둘이 붙으면 `<w:p/>`를 넣습니다. 붙은 두 표는 하나로 합쳐지기 때문입니다.
6. `document.xml` = 원본의 `<w:body>` 여는 태그까지 + 새 본문 + 원본의 `</w:body>`부터 끝까지.
   - 이름공간 선언·`mc:Ignorable`·문서 배경은 그대로 남습니다.
7. ZIP은 `document.xml`과(필요할 때만) `numbering.xml`만 새로 압축하고, 나머지 항목은 raw로 복사합니다.

### 4.4 바뀐 단락 다시 쓰기

**`w:pPr`(단락 속성)**

- 단락 속성(정렬·간격·들여쓰기·역할)이 원본과 같으면 원본 `w:pPr` 문자열을 그대로 씁니다. 스타일 참조·번호·탭·테두리·구역 나눔이 살아남습니다.
- 다르면 새로 만듭니다. 원본의 `w:pStyle`과, 역할이 같을 때는 `w:numPr`도 이어받습니다.

**글자 조각(run)**

- 원본 단락의 `w:r`마다 가져오기가 읽은 서식을 계산해 `서식 키 → 원본 w:rPr 문자열` 표를 만듭니다.
- 새 조각의 서식 키가 표에 있으면 **원본 `w:rPr`을 그대로** 씁니다. 그래서 문자 스타일·테마 글꼴·언어 속성이 남습니다.
- 표에 없으면 기존 내보내기의 `rPr`로 만듭니다.

**글자 아닌 원본 내용**

- 원본 단락 안의 그림(`w:drawing`)·필드·각주 참조·책갈피·주석 범위는 가져오기가 글자로 바꾸지 않습니다. 그래서 단락을 다시 쓰면 위치를 정확히 알 수 없습니다.
- 1단계에서는 이런 것을 가진 단락이 바뀌면 다음처럼 합니다.
  - **그림 `w:drawing`·`w:pict`·`w:object`가 든 `w:r`**: 단락 끝에 원본 그대로 다시 붙입니다. 그림이 사라지지 않게 하려는 것입니다.
  - **책갈피·주석 범위 표시**: 단락 맨 앞에 원본 그대로 둡니다. 쌍이 깨지지 않게 하려는 것입니다.
  - **필드·각주 참조**: 결과 글자만 남습니다.
  - 저장 보고(SaveReport)에 "단락 n개: 그림·필드 위치가 바뀔 수 있음"으로 알립니다.
- **변경 추적(`w:ins`/`w:del`)**: 추적 표시가 든 단락이 바뀌면, 1단계에서는 그 단락을 추적을 받아들인 결과로 씁니다. 삽입은 남고 삭제는 사라지며, 저장 보고에 알립니다. 바뀌지 않은 단락의 추적 표시는 그대로입니다.

**목록**

- 역할은 그대로인데 번호가 필요하면 다음 순서로 고릅니다.
  1. 원본 `numPr`를 씁니다.
  2. 원본에 없으면 바로 앞 같은 종류 단락의 `numId`를 씁니다.
  3. 그것도 없으면 `numbering.xml`에서 같은 종류(글머리표·번호)의 첫 `w:num`을 씁니다.
  4. 그래도 없으면 `numbering.xml`에 `abstractNum`과 `num`을 덧붙입니다. 이때 abstractNum은 첫 `w:num` 앞에 넣습니다(스키마 순서).
- `numbering.xml`이 아예 없으면 새로 만들기로 넘어갑니다(2장 마지막 갈래). 부품·관계·콘텐츠 형식을 새로 만드는 것은 2단계에서 합니다.

**제목**

- 원본 `styles.xml`에서 그 수준의 제목 스타일 id를 찾아 씁니다(`docxContext.headings`의 역방향).
- 없으면 `w:outlineLvl`만 씁니다. 원본에 없는 `Heading1` 같은 참조를 만들지 않습니다.

### 4.5 바뀐 표

- 병합(gridSpan·vMerge)이 없고 행·열 수가 같으면 원본 `w:tr`/`w:tc`를 순서대로 맞춥니다.
  - 바뀐 셀만 `w:tcPr` 뒤 내용을 다시 씁니다. 셀 안 단락에는 4.4를 똑같이 적용합니다.
  - 표 속성(`w:tblPr`: 표 스타일·테두리)·셀 속성(`w:tcPr`)·행 속성은 원본 그대로입니다.
- 그 밖의 경우(행·열을 넣거나 지움, 병합)에는 표 전체를 기존 내보내기로 다시 만듭니다.
  - 이때 원본 `w:tblPr`(표 스타일)는 이어받습니다. 저장 보고에 알립니다.

### 4.6 참조 무결성

| 참조 | 1단계 규칙 |
|---|---|
| 관계(`*.rels`의 rId) | 새로 만드는 XML은 rId를 쓰지 않습니다(이미지·링크를 새로 만들지 않음). 원본 그대로 옮긴 요소의 rId는 원본 rels에 그대로 있습니다. 그래서 rels는 바꾸지 않습니다. |
| 번호(`numId`) | 4.4 목록 규칙. 새 `numId`·`abstractNumId`는 원본 최댓값 + 1부터 씁니다. |
| 스타일(`pStyle`·`rStyle`) | 원본 스타일 id만 씁니다(재사용한 pPr·rPr, 4.4 제목 규칙). 원본에 없는 id를 만들지 않습니다. |
| 책갈피·주석 id | 원본 요소를 옮길 뿐 새 id를 만들지 않습니다. 지워진 단락에 있던 짝은 함께 사라지고, Word는 짝 없는 끝 표시를 무시합니다. |
| `[Content_Types].xml` | 바꾸지 않습니다(새 부품 없음). |
| 문서 속성(docProps) | 그대로 둡니다. Word가 다음 저장 때 단어 수 등을 고칩니다. |

### 4.7 새 노드(1단계 범위 밖)

- 문서 페이지에 새로 넣은 그림·도형·미디어처럼 흐름에 속하지 않는 노드는 지금 내보내기도 쓰지 않습니다. 그러니 이것은 손실이 아닙니다.
- 흐름에 들어가는 새 단락·표는 4.3의 "새 항목"으로 씁니다.

## 5. XLSX

- **편집 단위**는 시트의 셀(`<c r="B3">`)입니다.
  - 가져오기는 시트마다 표 페이지를 만듭니다(긴 시트는 여러 페이지).
  - 지도: 시트 부품 이름, 표 노드 id들, 셀마다 지문(`행:열 → 값·수식·서식 키` 해시).
  - 칸마다 지문을 두면 지도가 크므로, **행마다 해시 하나**만 둡니다. 바뀐 행 안에서는 원본 셀 값과 직접 비교합니다.
- **저장**은 바뀐 행의 바뀐 셀만 원본 `<c>` 요소를 바꿔 씁니다. `s`(스타일) 속성은 유지합니다.
  - 글자 값은 `t="inlineStr"`로 씁니다. `sharedStrings.xml`을 건드리지 않으려는 것입니다(Excel이 다음 저장 때 정리함).
  - 숫자는 `<v>`로 씁니다.
  - 수식 셀의 수식을 고치면 `<f>`를 바꾸고 캐시 값 `<v>`는 지웁니다.
  - 수식을 지우고 값을 넣으면 `<f>`를 없앱니다.
- **행·열 추가·삭제**는 1단계에서 하지 않습니다.
  - 셀 수·행 수가 바뀐 시트는 그 시트 부품만 새로 쓰고(기존 `exportXlsx`의 시트 XML), 다른 시트·부품은 원본 그대로 둡니다.
  - 이때 그 시트의 병합·조건부 서식·데이터 유효성이 없어질 수 있다고 알립니다.
- **재계산**: 값이 바뀌면 다른 수식의 캐시 값이 낡습니다.
  - 그래서 `workbook.xml`의 `<calcPr>`에 `fullCalcOnLoad="1"`을 넣습니다. 바꾸는 것은 이 속성 하나뿐입니다.
  - 수식이 사라진 셀이 있으면 `xl/calcChain.xml`에서 그 셀 항목을 지웁니다(Excel 복구 대화상자 방지).
- **그대로 두는 것**: 셀 서식(styles.xml)·테마·차트·그림·피벗·정의된 이름·시트 보호.
- 고친 셀의 서식은 원본 `s`를 그대로 쓰므로, 새 서식을 styles.xml에 넣지 않습니다.
  - 오메에서 셀 굵게·색을 바꾼 것은 1단계에서 반영하지 않고 알립니다.
  - 2단계에서 셀 서식(xf)을 덧붙입니다.

## 6. HWPX

- **편집 단위**는 각 구역 파일(`Contents/sectionN.xml`) `hs:sec`의 최상위 `hp:p`입니다.
  - 한글은 표·그림을 문단 안 `hp:run`의 컨트롤로 둡니다. 그래서 표도 그 문단 블록에 속합니다.
- **문단 다시 쓰기**는 DOCX 4.4와 같은 방식입니다.
  - 문단 속성이 같으면 원본 `paraPrIDRef`·`styleIDRef`를 유지합니다.
  - 글자 조각은 `서식 키 → 원본 charPrIDRef` 표로 재사용합니다.
  - 표에 없는 서식은 `header.xml`의 `hh:charProperties`에 새 `hh:charPr`를 덧붙입니다. id는 원본 최댓값 + 1이고, `itemCnt`도 함께 고칩니다.
  - 문단 속성이 다르면 `hh:paraPr`를 덧붙입니다(같은 방식).
- **줄 배치 캐시**: 다시 쓴 문단에서는 `hp:linesegarray`를 뺍니다. 한글이 열 때 다시 계산합니다.
- **표·그림 컨트롤**: 바뀐 문단 안의 표·그림·머리말 같은 컨트롤 `hp:run`은 원본 그대로 다시 붙입니다.
  - 표 셀을 고치면 DOCX 4.5와 같이 셀(`hp:tc`) 안 `hp:subList` 문단만 바꿉니다.
- **그대로 두는 것**
  - 바꾸지 않습니다: `version.xml`·`settings.xml`·`content.hpf`·`BinData/*`·`Preview/*`·`META-INF/*`. `mimetype`은 첫 항목·무압축으로 raw 복사합니다.
  - 미리보기(`Preview/PrvText.txt`·`PrvImage.png`)는 낡지만 지우지 않습니다. 한글이 다음 저장 때 고칩니다.

## 7. 무편집 저장, 서명, 암호

- **무편집 저장은 바이트가 같아야 합니다.** 모든 블록이 그대로이고 새 항목이 없으면 원본 asset bytes를 그대로 돌려줍니다. ZIP을 다시 쓰지도 않습니다.
- **디지털 서명**: 패키지에 서명이 있으면 내용을 바꾸는 순간 서명이 깨집니다.
  - 서명 표시: DOCX·XLSX는 `_xmlsignatures/`와 `package/2006/relationships/digital-signature/origin` 관계, HWPX는 `META-INF/signatures.xml`.
  - 편집 저장이면 서명 부품은 그대로 두고, 저장 보고에 "서명이 무효가 됨"을 알립니다(개발 PC 검토, 2026-11-12).
  - 무편집 저장이면 원본 bytes 그대로이므로 서명이 유지됩니다.
- **암호**
  - **DOCX·XLSX 암호 파일**(CFB `EncryptedPackage`): 지금 열지 못하므로 1단계 범위 밖입니다.
  - **HWPX 문서 암호**: 지금처럼 복호화한 평문 패키지에서 지도를 만듭니다.
    - asset에는 **평문을 두지 않고** 원본(암호화된) bytes를 둡니다. 원본은 `assetId` 하나로만 참조합니다(중복 저장 방지, 용량 부서의 자산 정리가 살아 있는 참조로 셉니다).
    - 저장할 때 세션 암호로 다시 풀어 수술하고, 평문 결과는 기존 `protectOutput` 경로가 다시 암호화합니다.
    - 세션 암호가 없으면(다른 세션에서 연 .omw) 새로 만들기로 넘어가고 지금처럼 암호를 묻습니다.
    - 무편집 저장이면 암호화된 원본 bytes를 그대로 돌려주는 것이 목표입니다. 1단계에서는 `protectOutput`이 다시 암호화하므로 내용만 같고 바이트는 다릅니다. 바이트까지 같게 하려면 `ui/actions.ts`의 저장 경로가 "이미 최종 bytes"를 받아야 해서, UI 쪽과 맞춰 2단계에서 합니다.
- **보호(문서 보호·시트 보호)**: 설정 부품을 그대로 두므로 유지됩니다.

## 8. 새로 만들기로 넘어가는 경우 (정직한 대체 처리)

아래 경우에는 지금처럼 문서 전체를 새로 만들고, 저장 보고에 이유를 한 줄 씁니다.

- `engine`이 다르거나 `hash`가 다르거나 asset이 없을 때(예: 오래된 .omw).
- 원본 부품을 다시 스캔한 결과가 지도와 맞지 않을 때(블록 수가 다름).
- 다른 파일에서 온 페이지가 섞였을 때. 이때 `source.name`이 다른 페이지는 1단계에서 넣지 않습니다.
  - 지금 "원래 형식으로 저장"은 모든 페이지를 씁니다. 그래서 섞인 문서는 새로 만들기로 넘어갑니다.
- DOCX `numbering.xml`이 없는데 목록을 새로 만들었을 때.

## 11. 구현 메모 (1단계 DOCX, 2026-11-12)

설계와 달라졌거나 코드 QA 뒤 더한 것을 적습니다.

- **블록 지도 위치**: 지도는 첫 페이지의 `page.source.office`에만 둡니다. 모든 페이지에 두면 .omw에 같은 지도가 페이지 수만큼 들어가기 때문입니다.
  - 첫 페이지를 지우면 지도가 없어지고, 저장할 때 "새로 만듭니다" 알림을 보냅니다.
  - 지도를 문서 수준(OmwDocument)으로 옮기는 일은 2단계에서 합니다(types.ts 담당과 상의).
- **표에 딸린 빈 문단**: 표 바로 뒤의 빈 `w:p`(Word가 표 뒤에 요구하는 문단)는 그 표에 딸립니다. 표를 지우면 함께 지워지고, 표 뒤에 새 문단을 넣어도 빈 줄이 생기지 않습니다.
- **표 서식 지문 `tp`**: 표 블록에는 가져올 때의 표 서식(열 너비·머리글 행·글꼴) 지문을 따로 둡니다(`OfficeSourceBlock.tp`).
  - 페이지보다 넓은 표는 가져오기에서 열 너비가 줄어듭니다. 그래서 원본을 다시 읽은 값과 비교하지 않고 이 지문과 비교합니다.
- **문단 안 원본 요소 되돌려 쓰기**: 바뀐 문단에서 다음 요소는 글자가 그대로이면 원본 요소를 같은 자리에 그대로 씁니다. 글자가 바뀌었으면 평문으로 쓰고 알립니다.
  - 대상: 하이퍼링크, 수식(`m:oMath`), 간단 필드(`w:fldSimple`), 문단 안 콘텐츠 컨트롤(`w:sdt`), 복합 필드(`fldChar` begin…end).
  - 그림·도형(`mc:AlternateContent`)·각주 참조는 원본에서 바로 앞에 있던 글자 12자 뒤에 다시 놓습니다. 그 글자가 없어졌으면 문단 끝에 놓고 알립니다.
- **run 서식 재사용**: 같은 서식 키의 원본 `w:rPr`가 여러 개면(숨김 글자·문자 스타일처럼 모델이 읽지 않는 차이) 같은 자리의 것을 씁니다.
- **문단 서식을 새로 쓸 때**: 모델에 없는 `w:pPr` 자식은 원래 순서대로 옮깁니다. 대상은 `keepNext`·`keepLines`·`pageBreakBefore`·`widowControl`·`pBdr`·`shd`·`tabs`·`sectPr` 등입니다.
- **셀 칠**: 셀 배경색을 바꾸면 원본 `w:tcPr`의 `w:shd`만 바꿉니다.
- **중첩 표 셀**: 바뀐 셀 안에 중첩 표나 컨트롤이 있으면 그 표 전체를 새로 쓰고 알립니다.
- **복제한 페이지·문단**: 같은 문단 id가 두 번 나오면 두 번째부터는 새 내용으로 씁니다.
  - 지금 페이지 복제(`duplicatePage`)와 Ctrl+D(`duplicateSelected`)는 문단 id를 새로 만들지 않습니다(`ui/actions.ts`, UI 쪽).
- **목록 이어 쓰기**: 새 목록 항목은 흐름에서 바로 앞 원본 목록 문단의 `numId`를 이어 씁니다.
  - `numbering.xml`이 없는 문서면 새로 만들고, `[Content_Types].xml` Override와 `document.xml.rels` 관계를 함께 넣습니다.
- **암호 DOCX**: `ui/actions.ts`는 Office 암호 파일을 풀어서 `open`에 넘깁니다. 원본 asset을 그대로 두면 풀린 패키지가 **평문**으로 .omw·저널에 들어갑니다.
  - 그래서 `OpenCtx.decrypted`가 참이면 asset과 지도를 만들지 않습니다(새로 만들기로 저장하고 알림).
  - **남은 일**: `ui/actions.ts`의 두 `fmt.open(…)` 호출에 `decrypted: !!officeSecret`를 넘겨야 이 보호가 켜집니다(UI 쪽에 부탁). 그 전까지는 암호 DOCX도 평문 원본이 asset으로 남습니다.
  - 2단계: 암호화된 원본을 asset으로 두고 저장할 때 세션 암호로 풀어 수술합니다(HWPX와 같은 방식).
- **이 PC의 Word**: COM `SaveAs2`가 숨은 상태에서 멈춥니다(새 문서도 같음). 그래서 Word 견본을 새로 만들지 못하고, 기존 Word 견본(`adobe-made/word_doc.docx`)으로 호환 시험을 했습니다. 열기(check)는 정상입니다.

### XLSX (2026-11-12)

- **시트 조각 잇기**: 시트가 여러 페이지로 나뉜 표는 이름이 같은 연속 조각을 머리글과 상관없이 잇습니다. 이어지는 조각의 첫 행(반복 머리글)은 버립니다.
  - 그래서 첫 머리글을 고쳐도, .omw를 다시 열었어도 행이 빠지지 않습니다.
  - 같은 이름의 표가 떨어져 두 번 나오면 새로 만들기로 넘어갑니다.
- **바뀐 행만, 바뀐 칸만**: 지도에는 행마다 해시 하나를 둡니다. 바뀐 행에서는 값(글자·수식)이 달라진 칸만 다시 씁니다.
  - 굵게·기울임·정렬·칠만 바뀐 칸은 쓰지 않고 알립니다(2단계: 새 xf).
  - 다시 쓰는 행에서 주소(r)가 없던 원본 칸에는 주소를 붙입니다.
- **숫자 칸**: 다음 경우에는 글(inlineStr)로 씁니다.
  - 숫자에 새 서식(날짜·백분율)이 필요하지만 칸 스타일에 그 서식이 없을 때.
  - 날짜·백분율 스타일 칸에 맨 숫자를 넣었을 때.
- **새로 만들기로 넘어가는 경우**(알림):
  - 공유·배열·데이터 표 수식의 대표 칸(`<f t="shared|array|dataTable" ref=…>`)이 바뀜.
  - Excel 표(ListObject) 머리글 칸이 바뀜. 머리글이 `tableColumn@name`과 맞아야 하기 때문입니다.
  - 매크로 통합 문서·서식 파일(`macroEnabled`, `template`) 패키지. .xlsx 이름으로는 열리지 않기 때문입니다.
- **수식**: 수식이 있던 칸이 값이 되면 `calcChain.xml`을 지웁니다(공유 수식에 딸린 칸 포함). 수식 칸에 값을 넣으면 열 때 다시 계산된다고 알립니다.
- **남은 것**: 중간 행 삭제·삽입은 칸 값을 자리대로 옮겨 쓸 뿐입니다. 다른 칸 수식의 참조는 고치지 않고, 알림만 냅니다.
  - 병합으로 가려진 칸에 넣은 글은 Excel에서 보이지 않습니다.

### HWPX (2026-11-12)

- **편집 단위**: 각 구역 파일의 최상위 `hp:p`입니다. 다시 쓰는 경우는 둘입니다.
  - 표·글상자가 없는 문단은 문단 단위로 다시 씁니다.
  - 표를 담은 문단은 그 문단의 글은 그대로이고 표 격자가 같을 때, 바뀐 칸의 `hp:subList` 문단만 다시 씁니다.
  - 머리말·꼬리말·각주 컨트롤의 subList는 본문 객체로 보지 않습니다.
- **모양 id**
  - 문단 모양: 원래 문단의 `hh:paraPr`를 **복제**해 정렬·여백(들여쓰기·왼쪽·다음)·줄 간격·제목/목록만 바꿉니다. 탭·줄 나눔·테두리·`hp:switch` 사본은 그대로입니다. 다른 문단의 모양을 빌려 쓰지 않습니다.
  - 글자 모양: 그 문단의 run들이 쓰던 charPr 가운데 같은 서식을 먼저 씁니다. 없으면 바로 앞 charPr을 복제해 바뀐 속성만 고칩니다. 장평·다른 언어 글꼴·강조점은 유지됩니다.
  - 새 모양은 header.xml 목록 끝에 붙이고 `itemCnt`를 고칩니다. 새 글꼴은 7개 언어 fontface에 모두 넣고 `fontCnt`를 고칩니다.
- **구역 설정**: `hp:secPr`가 든 문단은 그 구역의 첫 문단으로 남습니다. 그 앞에 넣은 새 문단은 뒤로 미뤄집니다.
  - 그 문단의 글을 지우면 secPr와 쪽 컨트롤(단·머리말·꼬리말·쪽 번호)만 남은 빈 문단이 됩니다.
- **줄 배치 캐시**: 다시 쓴 문단에서는 `hp:linesegarray`를 뺍니다. 한글이 열 때 다시 계산합니다.
  - 오메가 처음부터 만드는 HWPX도 이 캐시 없이 한글에서 열립니다.
  - 조판 부서의 lineseg 파서는 **바뀌지 않은 문단의 lineseg만** 읽게 됩니다.
- **새로 만들기로 넘어가는 경우**(알림): 새 표, 구조가 바뀐 표(병합 포함), 글자가 바뀐 글상자·객체 문단, 글 사이에 필드(`fieldBegin`/`fieldEnd`: 하이퍼링크 등)가 있는 문단, 문서에 없는 제목·목록 모양.
- **암호 HWPX**: 1단계에서는 지도를 만들지 않습니다. 복호화한 패키지를 asset으로 두지 않기 위해서입니다.
- **표 칸**: 칸 글만 바뀌고 rich 문단이 맞지 않으면, 원래 칸 문단의 모양으로 씁니다(DOCX도 같음).

### 쪽 설정·쪽 나누기 (2026-11-12, `officesurgeon/layout.ts`)

- 원본을 가져오기로 다시 읽은 쪽 배치(쪽 나눔이 놓인 항목, 구역과 용지·여백)를 지금 쪽들과 비교합니다.
- 용지·방향·여백이 바뀐 구역: 그 구역의 `w:pgSz`·`w:pgMar`(DOCX) / `hp:pagePr`(HWPX)만 다시 씁니다. 머리말 참조·단·격자 등 구역의 다른 설정과 다른 구역은 원본 그대로입니다.
- 새 쪽 나누기(Ctrl+Enter): DOCX는 그 항목 앞에 Word의 쪽 나눔 문단 하나, HWPX는 그 문단의 `pageBreak="1"`만 바꿉니다.
- 새로 만들기로 넘어가는 경우(알림): 구역을 더하거나 뺌, 원래 있던 쪽 나눔을 없앰, 쪽 나눔이 있던 항목을 지움, 빈 쪽, 표 앞 글이 있는 HWPX 문단 중간의 나눔.
- 가져오기 규칙이 바뀌어(쪽 나눔만 있는 문단은 항목이 아님) DOCX·HWPX 지도 판을 `WORD_ENGINE_VERSION = 2`로 올렸습니다. 이전 .omw의 지도는 쓰지 않고 새로 만들기 + 알림입니다(XLSX는 그대로 1).

### 머리말·꼬리말·쪽 번호 (2026-11-12, `officesurgeon/hf.ts`)

- 지도에 `hf: 1`(머리말을 읽은 가져오기)이 있을 때만 비교합니다. 그 전 .omw의 쪽에는 머리말이 없으므로 비교하지 않고 원본의 머리말을 그대로 둡니다.
- DOCX: 원본을 가져오기로 다시 읽은 구역별 머리말과 지금 쪽의 구역별 머리말을 같은 규칙(`office.ts` docxHFSections)으로 부품 목록으로 만들어, 부품마다 내용 지문(필드는 종류로, 보인 값은 빼고)을 비교합니다.
  - 바뀐 부품만 다시 씀(`header{n}.xml` 하나). 본문 `document.xml`은 바뀐 것이 없으면 그대로 둡니다. 다시 쓴 부품에 그림·도형이 있었으면 알림.
  - 새 갈래: 쓰지 않은 이름의 부품 + `rIdOmwHF{n}` 관계 + 내용 형식 Override + 그 구역 `w:sectPr` 맨 앞에 참조. 다시 연결: 참조만 뺌(부품은 남김).
  - `w:pgNumType`·`w:titlePg`는 CT_SectPr 순서 자리에 그 요소만, 홀짝은 settings의 `evenAndOddHeaders` 하나만. settings.xml이 없는 원본에서 홀짝을 켜면 새로 만들기.
- HWPX: 가져올 때의 머리말 지문(`hfKey`)과 같으면 아무것도 쓰지 않고(바이트 동일), 다르면 새로 만들기 + 알림. 한글은 머리말을 본문 문단 속 컨트롤로 두어 이번 단계에서는 문단 수술을 하지 않습니다.
- 모델 4(같은 날): DOCX 제목 스타일 문단의 run에 `w:sz`·`w:b`가 없으면 styles.xml의 그 스타일(basedOn 따라)의 크기·굵기·글꼴로 읽습니다. 전에는 26 − 3 × 수준 pt 굵게로 어림해, 표 칸 하나만 고쳐도 `w:sz 40` + `w:b`가 박혀 Word에서 20 pt로 보였습니다(`adobe-made/word_doc.docx`, `tests/officesurgeon/headingCell.test.ts`). 모델 4 전 지도는 원본을 예전 어림으로 다시 읽어 비교합니다(`docxContext` oldHeadings, 줄 간격 모양은 `MODEL_WORD_MULTIPLE = 3` 그대로).

### 그림 (2026-11-13, 2단계 "새 그림", `officesurgeon/pics.ts`)

- 지도 모델 5: 본문 그림을 IMAGE 노드로 읽고(그림만 있는 문단은 항목이 아님), 그림마다 부품·최상위 요소 번호·그 요소 안 그림 번호·지문을 `OfficeSourceMeta.pics`에 둡니다. 모델 4까지의 지도는 원본을 그림 없이 다시 읽어 비교합니다(`MODEL_HEADING_STYLES = 4`로 제목 스타일 규칙은 그대로).
- 안 바꾼 그림: 쓰지 않음. 바꾼 그림: DOCX는 `wp:extent`·`a:xfrm`·`a:srcRect`·`positionH/V`만, 배치 종류·바이트가 바뀌면 그 `w:drawing`만 새로(docPr 유지). HWPX는 그 `hp:pic`만 새로(id·`hc:img`·설명 유지). 지운 그림: 그 요소만, 그림만 있던 문단은 문단째. 새 그림: DOCX `word/media/omw-imageN` + `rIdOmwImgN` + 내용 형식 Default(없을 때만) + 문서 요소에 `xmlns:wp`·`xmlns:r`(없을 때만), HWPX `BinData/omwimageN` + content.hpf 항목.
- 글이 바뀐 문단 안의 그림을 바꾸면 새로 만들기 + 알림. 4.6의 "rels는 바꾸지 않습니다"는 새 그림이 있을 때만 예외입니다.

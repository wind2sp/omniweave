# 문서 본문 흐름과 바로 입력 (DOC_FLOW)

> 작성: 문서 편집 핵심 부서, 2026-11-13. 출발점: 제품 검토 의견 "아직 PPT 수정하는 느낌이지 문서작업 느낌이 없어."
> 관련: WORD_HWP_FEATURES.md 6장 결손 8(본문 자동 흐름), UNIFIED_STYLES.md 4.11 `TextFrame`, LAYOUT_TRUTH.md.

## 1. 문제

- '문서' 쪽의 본문은 쪽마다 따로 놓인 글상자(TEXT 노드)였습니다. 클릭하면 개체로 선택되고(손잡이·X/Y), 두 번 눌러야 글상자 하나 안에서만 입력됩니다.
- 글이 넘쳐도 다음 쪽으로 흐르지 않습니다. 가져오기(DOCX/HWPX)에서만 `paginate()`가 한 번 쪽을 나눕니다(문단 통째로).
- 문단 묶음(`keepNext`·`keepLines`)은 저장만 되고 화면에는 효과가 없습니다.

## 2. 모델 — "흐름 틀(frame)을 쪽에 펼쳐 둔다"

핵심 결정: **이야기(story)를 따로 저장하지 않고, 조판 결과를 쪽의 노드로 펼쳐 저장한다.**
렌더러·PDF/PNG/인쇄·DOCX/HWPX 내보내기·Office Surgeon·썸네일은 지금처럼 `page.nodes`만 보면 되므로 하나도 바뀌지 않습니다.
흐름 엔진은 펼친 틀을 다시 모아(gather) 이야기를 만들고, 조판(layout)해 다시 펼칩니다(materialize).

| 요소 | 필드 | 뜻 |
|---|---|---|
| 노드 | `flow?: true` (TEXT·TABLE·IMAGE) | 본문 흐름에 속한 틀/개체. 없으면 지금처럼 떠 있는 개체(머리 장식, 도형 등) |
| 문단 | `flowSplit?: 1 \| 2` | 쪽 끝에서 잘린 문단의 앞부분. 1 = 런 경계에서, 2 = 런 안에서 잘림(합칠 때 마지막 런과 다음 첫 런을 붙임). 이 줄은 마지막 줄이 아님(양쪽 정렬 유지, 문단 뒤 간격 없음) |
| 문단 | `flowCont?: string` | 잘린 문단의 이어짐(다음 쪽 맨 위). 값 = 원래 문단 id. 들여쓰기·문단 앞 간격·목록 표시 없음 |
| 표 | `flowCont?: string` | 쪽을 넘어 나뉜 표의 이어짐(값 = 머리 표 id). 머리글 행은 반복 |
| 문단 | `widowControl?: false` | 과부·고아 줄 처리 끔(없으면 켬 — Word 기본) |

- **구간(segment)**: 첫 쪽·쪽 나눔(`breakBefore` 없음)·구역 나눔(`"section"`)으로 시작하는 쪽부터, `breakBefore: "flow"`인 쪽들까지.
  구간 하나가 이야기 하나입니다. 사용자가 넣은 쪽 나눔·구역 나눔은 구간 경계라 흐름이 넘지 않습니다.
- 구간 안에 `flow` 노드가 하나라도 있으면 흐름 구간입니다. 예전 문서(표시 없음)는 흐름 구간이 아니라 지금과 똑같이 보이고 편집됩니다.
- 이야기 = 구간의 쪽 순서 → 쪽 안에서 y 순서로 흐름 노드를 읽어, 잘린 문단·표를 합친 블록 목록
  `{ paras: TextParagraph[]; objs: { node; before: 문단 id } [] }`. 개체(표·그림)는 "어느 문단 앞" 닻으로 둡니다.
  이야기는 항상 문단으로 끝납니다(Word처럼 마지막 빈 문단).
- 머리말·꼬리말(`Page.hf`)은 구역 첫 쪽에 있으므로 흐름이 쪽을 늘리고 줄여도 그대로입니다. 쪽 번호 필드는 쪽마다 그 자리에서 계산되므로 흐름 결과 쪽 수를 그대로 따릅니다.

### 2.1 내보내기 호환

- `io/office.ts collectFlow`가 `flowCont` 문단을 앞 문단에 합치고(`flowSplit` 2는 런을 다시 붙임), `flowCont` 표를 머리 표에 합칩니다.
  합친 문단은 원래 id와 원래 런을 그대로 가지므로 Office Surgeon의 지문이 같고 원본 바이트가 그대로 복사됩니다.
- 그 밖의 형식(Markdown·HTML·텍스트)은 `core/flow.ts storyParas()`로 같은 합치기를 씁니다(2단계에서 모든 내보내기에 연결).

## 3. 조판 (`core/flow.ts`)

- 문단 높이는 더하기입니다(`core/text.ts`가 문단을 위에서 아래로 쌓음) → 문단마다 한 번 조판해 캐시(`WeakMap<TextParagraph, …>`).
  immer가 바뀌지 않은 문단 객체를 그대로 두므로, 한 글자 입력은 그 문단 하나만 다시 조판합니다.
- 쪽 채우기(Word 기준):
  1. `pageBreakBefore` 문단은 새 쪽에서 시작(구간 첫 쪽 맨 위면 그대로).
  2. 문단이 남은 높이에 다 들어가면 놓습니다.
  3. 안 들어가면 줄 단위로 자릅니다. `keepLines`면 자르지 않고 다음 쪽으로. 과부·고아 처리(기본 켬): 앞에 2줄 이상, 뒤에 2줄 이상 남을 때만 자름.
     빈 쪽 맨 위에서도 안 들어가면(쪽보다 긴 문단) 들어가는 만큼 자릅니다(무한 반복 방지).
  4. `keepNext`: 문단과 다음 블록의 첫 줄(들)이 같은 쪽에 있어야 합니다. 묶음 사슬 전체가 쪽 하나보다 길면 Word처럼 묶음을 무시합니다.
  5. 표: 행 단위로 나눕니다. 행이 쪽보다 높으면 그 행만 쪽을 넘쳐 그립니다(행 안 쪼개기는 2단계). 머리글 행 반복.
  6. 그림(흐름 개체): 블록으로 쌓고, 안 들어가면 다음 쪽(쪽보다 크면 그대로 넘침).
- 펼치기: 쪽마다 연속 문단 → TEXT 틀 하나(본문 상자 위치·너비), 표·그림 → 그 자리. 이전 틀과 내용·위치가 같으면 **같은 객체를 다시 씀**(렌더 캐시·해시 유지).
  쪽이 모자라면 앞 쪽과 같은 종류·용지·여백·바탕·바탕쪽으로 `breakBefore: "flow"` 쪽을 만들고, 남으면 흐름 쪽(떠 있는 개체가 없는 쪽)을 지웁니다.
- 증분: 편집은 그 구간만 다시 흐르게 합니다. 바뀌지 않은 문단은 조판 캐시, 바뀌지 않은 틀은 객체 재사용 → 100쪽에서도 쪽 수 × (캐시 조회) 수준.

### 3.1 HWP/HWPX

한글 경로는 LAYOUT_TRUTH의 lineseg가 정답입니다. 1단계 흐름은 같은 `layoutText` 줄바꿈을 쓰고, 한글의 쪽 나눔 정보(lineseg `vertpos` 리셋)는
가져올 때 쓰지 않습니다. 2단계: 손대지 않은 문단은 lineseg 줄을 그대로, 고친 문단만 우리 조판(LAYOUT_TRUTH 6장 4번과 같은 계획). 한글 기본값은
외톨이줄 보호 끔이므로 HWPX 가져오기에서 `widowControl: false`를 넣습니다(2단계, `office.ts`는 그림 부서 작업 중).

## 4. 편집 (`ui/docFlow.ts`, `ui/FlowEditor.tsx`)

- 화면 위 글상자(contenteditable) 대신 **캔버스 위 커서**: 숨은 textarea가 키·IME·클립보드를 받고, 커서·선택 영역은 캔버스 위 DOM 층에 그립니다
  (그리기 설정은 건드리지 않음). 글은 캔버스가 실제 조판 그대로 그리므로 편집 중에도 화면이 인쇄 결과와 같습니다.
- 위치 = 이야기 안의 `{p, o}`(core/richtext.ts의 `Pos`). 편집은 모두 `core/richtext.ts`의 순수 함수로 이야기 문단에 적용 → 흐름 → 한 번에 커밋.
- 한글 조합: 조합 중인 글자를 이야기에 임시로 넣어 실제 자리에서 조판·표시하고(되돌리기 기록 없음), `compositionend`에서 확정합니다.
- 입력 묶음: 연속 입력은 한 번의 되돌리기(첫 글자에서 기록, 이어지는 글자는 같은 단계를 갱신, 0.8초 멈춤·커서 이동·다른 명령에서 끊음).
- 키: 방향키·Home/End·Ctrl+Home/End·PageUp/Down·Shift 선택·Ctrl+←/→(단어)·Ctrl+A(구간 본문 전체)·Enter·Shift+Enter(줄 바꿈)·Backspace/Delete
  (쪽 경계를 넘어서도)·Ctrl+B/I/U·Ctrl+L/E/R/J·Ctrl+Enter(쪽 나눔)·Ctrl+Z/Y·Tab(목록 수준)·Esc(편집 끝).
- 마우스: 본문 아무 데나 클릭 → 그 자리 커서(손잡이 없음). 끌기 = 선택, 두 번 = 단어, 세 번 = 문단, Shift+클릭 = 선택 넓히기. 머리말·꼬리말 여백 두 번 클릭은 지금처럼 머리말 편집.
- 커서가 다른 쪽으로 가면 그 쪽으로 화면이 넘어갑니다(지금 캔버스는 한 쪽씩 보여 줌 — 이어 보기는 화면 부서의 문서 모드 작업).
- 리본: `RichApi`를 그대로 구현해 굵게·글꼴·문단·목록·제목이 흐름 편집에도 동작합니다.
- 복사·붙여넣기: 일반 글 + HTML(서식, Word에서 붙여넣기 → `htmlToSegments`).

## 5. 호환

- 예전 .omw: `flow` 표시가 없으므로 모양·편집 방식이 그대로입니다. "본문 흐름으로 바꾸기" 명령이 본문 상자(왼쪽 여백에서 시작하는 회전 없는 글상자·표)를
  흐름으로 표시하고 다시 흐르게 합니다(한 번의 되돌리기).
- 새로 가져온 DOCX/HWPX: 본문 상자와 표에 `flow`를 붙여 가져옵니다. 쪽 나눔은 가져올 때의 결과 그대로(문단 통째)이고, 처음 편집하는 구간부터 줄 단위 흐름이 됩니다
  (정답 자료 시험의 가져오기 결과가 바뀌지 않음).
- PDF 쪽은 원본 쪽 그림(PDF 노드)이라 흐름이 아닙니다(글자 승격 뒤 흐름 변환은 2단계).
- 디자인·슬라이드 쪽: 바뀌지 않음(개체 편집).

## 6. 단계

1. **(이번) 흐름 + 바로 입력**: 모델 필드, `core/flow.ts`(모으기·조판·펼치기·위치↔좌표), collectFlow 합치기, 캔버스 커서 편집기, 가져오기 표시,
   문서 템플릿(빈 문서·분기 보고서·공문)을 흐름 본문 + 제목 스타일 + 진짜 표로.
2. 이어 보기(쪽을 세로로 이어 스크롤) — 화면 부서와 함께. 머리말이 길면 본문을 밀어 내리기. 표 행 안 쪼개기, 표 셀 안 커서(지금은 셀 편집기).
   인라인 그림(글자처럼 줄 안에 놓임: `TextRun.inline?: { nodeId }`)과 그림 부서의 IMAGE 노드 연결. Markdown/HTML 내보내기의 `storyParas` 연결.
3. HWPX lineseg 그대로 쓰기(손대지 않은 문단), 각주(결손 7)를 쪽 아래로, 다단.

## 7. 1단계 결과 (2026-11-13)

- 된 것: 모델 필드(`flow`·`flowSplit`·`flowCont`·`widowControl`), `core/flow.ts`(모으기·조판·펼치기·위치↔좌표), `collectFlow` 합치기(DOCX/HWPX·Surgeon은
  잘린 문단을 원래 한 문단·원래 런으로 씀), 캔버스 위 커서 편집기(`ui/docFlow.ts`·`ui/FlowEditor.tsx`), 가져온 DOCX/HWPX 본문 `flow` 표시,
  "본문 흐름으로 바꾸기" 명령(쪽 메뉴), 문서 템플릿 3종(빈 문서·분기 보고서·공문)을 흐름 본문 + 제목(h1/h2, 다음 문단과 함께) + 진짜 표 + 머리말·꼬리말(쪽 번호)로.
- 입력 중 글자: 캔버스가 실제 조판 그대로 그리므로 표시 상태와 똑같이 또렷하고 줄 나눔도 같습니다(DOM 편집 상자 없음). 글상자 편집기(`RichTextEditor`)는
  `transform: scale` 대신 CSS `zoom` + 불투명 배경으로 바꿔 Chromium이 LCD 글자로 그리게 했습니다.
- 성능(브라우저, 100쪽·900문단, 다른 부서 작업과 같은 PC에서 잰 값): 한 글자 입력 중앙값 약 15 ms(엔진 부분 3 ms), Enter(뒤 쪽이 모두 밀림) 중앙값 약 39 ms
  (엔진 다시 흐름 5 ms + 줄 표 6 ms, 나머지는 쪽 목록 썸네일 다시 그리기). 처음 흐름(900문단 → 100쪽) 85–200 ms.
  속도를 위해 `core/text.ts`에 문단별 줄 캐시(같은 문단 객체·너비면 다시 조판하지 않음), `hfInfo` 서명 비교를 할당 없이, 쪽 목록 행을 `memo`로.
- 남은 것(2단계): 이어 보기(세로 스크롤 연속 쪽), 표 셀 안 커서·행 안 쪼개기, 인라인 그림 자리, 머리말이 본문 밀어 내리기, Markdown/HTML 내보내기의
  `joinPieces`, HWPX `widowControl: false`·lineseg 그대로 쓰기, 쪽 경계를 넘는 Shift 선택은 구간(쪽 나눔 사이) 안에서만.

## 8. 2단계 진행 (2026-11-13, 브랜치 `docflow-2`)

- 그림 부서 `doc-gaps-4` 병합. 가져온 그림 중 `place.mode: "inline"`은 흐름 블록으로 표시(`markFlowInPlace`), 떠 있는 그림은 지금처럼 쪽 위 개체.
- **글자처럼(인라인):** `TextRun.obj { id, w, h }` + 글자 U+FFFC 한 자. `layoutText`가 개체 너비만큼 자리를 두고 줄 높이를 늘려 개체 아래끝을 기준선에
  맞춥니다(조각 글자는 보이지 않는 U+200B). `reflowSegment`가 그 줄 위치에 IMAGE 노드를 놓고 `place = { mode: "inline", para, offset }`을 채워
  그림 부서 저장 코드가 그대로 씁니다. `collectFlow`는 개체 런을 글에서 뺍니다. 크기를 바꾸면 런 크기가 따라갑니다.
- **넣기:** 문서 모드에서 그림 넣기(`placeImage`)는 커서 자리에 글자처럼, 표 넣기는 문단을 나눠 그 사이 블록으로.
- **레이아웃 옵션 버튼(Word 위치: 선택한 그림 오른쪽 위):** 글자처럼 / 정사각형 / 위·아래 / 글 뒤로 / 글 앞으로. 정사각형은 지금 위·아래와 같게
  (글이 옆으로 감싸는 줄 단위 배제는 다음), 글 뒤·앞은 쪽 위 개체(`place.wrap`).
- **표:** 흐름 표를 한 번 누르면 칸 편집(손잡이 없이), 마지막 칸에서 Tab → 행 추가 후 그 행 첫 칸, 칸 편집기도 CSS zoom(선명). 흐름 밖에서 바뀐 흐름 쪽
  (칸 글, 행 추가, 그림 크기·삭제, 문단 대화상자)은 같은 되돌리기 단계 안에서 다시 흐릅니다(`docFlow` 정리 구독).
- **텍스트 경계:** 문서 모드에서 본문 상자 점선은 기본 숨김, 보기 메뉴 "텍스트 경계"로 켬.
- 남은 것: 표 칸 안 커서를 흐름 편집기로(지금은 칸 편집기), 표 이동·크기 손잡이·열 경계 끌기, 행 안 쪼개기, 표 앞뒤 방향키 이동, 정사각형 감싸기(줄 배제),
  떠 있는 그림·도형의 문단 고정(앵커 이동), Shift 선택을 쪽 나눔 너머로, Word COM 비교.

## 9. 각주·미주와 Word·한글 쪽 나눔 (2026-11-13, 브랜치 `docx-pages-notes`)

- 가져온 DOCX/HWPX는 이제 가져올 때 흐름으로 쪽을 나눕니다(Word: 쪽 끝에서 문단을 자름·과부·고아·머리말이 미는 본문, 한글: lineseg의 쪽 시작).
  표·그림만 있는 구간에는 빈 문단을 만들지 않습니다(`reflowPages(pages, true)`).
- 각주·미주: 참조 런(`TextRun.note`)이 각주 글을 들고 다니고, 흐름이 번호를 매기고 쪽 아래 각주 영역·문서 끝 미주를 펼칩니다
  (`core/notes.ts`, 노드 `notes`). 흐름 편집기에서 Alt+Ctrl+F / Alt+Ctrl+D, 각주 영역은 글상자처럼 편집 → 각주로 되돌아감.
  자세히 FIDELITY_DOCX.md 4장.

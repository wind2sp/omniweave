# 이미지 크기 키우기(업스케일)

2026-11-21 이미지 부서. 사용자 요청: 흐릿하거나 깨진 저해상도 그림을 **품질을 살려** 키운다(세부 복원·JPEG 깨짐 제거). 이미지 문서·PSD 레이어·문서에 놓인 그림 모두.

## 1. 쓰는 법과 구조

- 명령 `image.upscale` '이미지 크기 키우기(업스케일)…': 이미지 메뉴, 리본(래스터·그림 하나를 골랐을 때 '크기 키우기', 이미지·디자인 모드), 캔버스 오른쪽 버튼 메뉴(래스터·그림 위).
- 대화상자 `src/ui/shell/UpscaleDialog.tsx`: 크기 2×·3×·4×·직접(비율 유지), 방법, 옵션, 미리보기(작은 그림을 눌러 고른 64 px 영역의 전/후), 적용 중 진행률과 취소(`cancelImageWork`).
- 방법
  | 이름 | 내용 |
  |---|---|
  | **고품질(AI, 기본)** | Real-ESRGAN 소형 모델(§4)을 오메 추론 엔진(Loom Infer)으로. 모델·잡음 강도·블록 줄이기는 **자동**(§5), 사용자가 바꿀 수 있음 |
  | 선명하게(빠름) | 고전 방식 `core/image/upscale.ts` "hq": Lanczos-3 → 가장자리 방향 다듬기(구조 텐서로 가장자리를 따라서만 평균) → 역투영 2회(결과의 면적 평균 = 원본 픽셀) → 2×2 이웃 범위로 고리 억제. 선택: 선명하게(언샤프)·잡음 줄이기(3×3 양방향) |
  | 부드럽게 | 쌍입방(Catmull-Rom) |
  | 픽셀 그대로 | 최근접(픽셀 아트) |
- 적용 `src/ui/upscaleActions.ts` — **실행 취소 한 번**:
  - 래스터 레이어(PSD 포함): 칠해진 영역을 왼쪽 위 고정으로 키움 → 레이어가 커지고 PSD 저장 때 큰 레이어로 씀(시험: 저장 → 다시 열기). 자르기 영역도 같은 배율, 배경 지우기 기록(matte)은 픽셀과 맞지 않아 뺌.
  - 그림(IMAGE): **원래 형식 유지**(JPEG→JPEG q0.95, PNG→PNG, WebP→WebP, 그 밖은 PNG). 색 변환 없이 디코드(`colorSpaceConversion: "none"`)하고 정보를 옮김(`core/image/imageMeta.ts`): JPEG은 Exif(방향 1로, PixelX/YDimension 새 크기)·XMP·ICC·IPTC·주석, PNG는 iCCP·sRGB·gAMA·cHRM·tEXt·zTXt·iTXt·eXIf·pHYs(배율만큼 키워 인쇄 크기 유지). WebP 정보는 옮기지 않음. 원본 자산은 기록에 남아 실행 취소로 돌아옴.
  - 대상이 캔버스 전체(연 그림, 레이어 하나뿐인 이미지)면 '캔버스도 같은 배율로' — 페이지 크기도 키움(Photoshop 이미지 크기).
  - .omw: 타일·자산으로 저장(시험: 저장 → 불러오기 같은 타일).
- 색 모드: **CMYK PSD는 거절**(잉크 비율을 지킬 수 없음 — RGB로 바꾸라고 안내), **32비트(HDR)도 거절**(흰색을 넘는 밝기를 8비트 작업 픽셀에서 되살릴 수 없음). 16비트 PSD는 오메 문서 모델이 8비트 작업 픽셀을 쓰므로 그 값으로 키운 뒤 16비트로 저장(대화상자에 안내). 엔진 자체는 16비트 입력을 그대로 처리함(시험). 조정·텍스트 레이어, SVG도 안내와 함께 거절.
- 한도: 결과 한 변 30,000 px, 100 MP, 한 번에 8배. AI는 4× 중간 결과가 120 MP 이하일 때(넘으면 고전 방식으로, 안내).

## 2. 고전 방식 품질 (원본을 4×(면적 평균) 줄였다가 다시 키워 원본과 비교)

`tests/image/upscale.test.ts`(합성 그림) — PSNR dB / SSIM

| 그림 | 고품질(hq) | 쌍입방 | 최근접 |
|---|---|---|---|
| fractal(부드러운 질감) | **45.48 / 0.9903** | 44.26 / 0.9876 | 37.56 / 0.9464 |
| lineArt(선·도형) | **20.25 / 0.8195** | 19.81 / 0.7828 | 18.90 / 0.8144 |
| detail(존 플레이트·획) | **18.68 / 0.8395** | 18.29 / 0.8241 | 16.26 / 0.6887 |

로컬 사진 5장(Windows 기본 배경의 가장 세밀한 512×384 영역, 저장소에 넣지 않음), 4×: hq가 쌍입방보다 0.5~3.9 dB 높음(예 49.70 vs 46.15, 38.22 vs 36.53, 31.29 vs 29.34). 매우 매끈한 영역에서는 차이가 ±0.06 dB 안.
단계별 기여(lineArt): Lanczos만 19.95 → 역투영 +0.05 → 가장자리 다듬기 +0.12 → 고리 억제는 PSNR −0.07이지만 SSIM +0.03(후광 없음).

## 3. AI 방식 — 엔진

- 모델 형식: `scripts/convert-esrgan.mjs`가 .pth(zip + pickle)를 **Python 없이** 읽음 — 허용한 opcode와 전역 4개(OrderedDict·_rebuild_tensor_v2·FloatStorage·HalfStorage)만, 모든 읽기에 범위 검사, 텐서는 저장소 안에 있어야 함, 그 밖은 오류(`tests/image/convertEsrgan.test.ts`: 다른 전역·호출·코드 실행 opcode·잘린 파일·끝없는 반복 거절). 고친 변환기로 다시 바꾼 .lwt 3개의 sha256이 저장소 것과 같음(2026-11-21 QA). 그래프: SRVGGNetCompact = conv3×3(3→64)+PReLU, n×[conv3×3(64→64)+PReLU], conv3×3(64→48)+픽셀 셔플(4), + 입력의 최근접 4×.
- 융합: **conv + PReLU 한 노드**(`act: "prelu"`, 기울기 `p`), **마지막 conv가 픽셀 셔플 위치로 바로 씀**(`a.shuffle`). 더하기(잔차)는 한 번뿐이라 노드로 둠. 노드 수 70 → 36(general), 38 → 20(anime).
- CPU(`infer/graph.ts`): 3×3은 기존 WebAssembly SIMD 커널, PReLU는 그 자리에서.
- WebGPU(`infer/graphGpu.ts`): 새 **conv3t** 커널 — 작업 그룹 하나가 8×8 픽셀 × 출력 8채널, 입력 8채널씩 10×10 조각과 8×8×9 가중치를 작업 그룹 메모리에 올려 64번 재사용, PReLU·셔플 출력 포함. 결과는 CPU와 최대 3e-6 차이(브라우저에서 대조).
  - f16 연산: 이 PC(NVIDIA Ampere)는 `shader-f16`을 지원하지만 아직 f32로 계산(가중치만 f16 저장). 다음 단계 후보.
- 속도(이 PC, 출력 1 MP당)
  | | 최적화 전(일반 conv4 커널) | 후(conv3t) |
  |---|---|---|
  | 커널만, general-x4v3 (256² 입력) | 300 ms | **170 ms** |
  | 커널만, animevideov3 | 158 ms | **92 ms** |
  | 전체 경로(작업자·타일·겹침·읽어오기), 512×384 → 2048×1536 | — | general **387 ms**, anime **211 ms** |
  | CPU(WebGPU 없음): node WebAssembly, 타일 하나 | general 약 4.8 s, anime 약 2.3 s | |
  | CPU, 앱 작업자 안 전체 경로(anime) | 약 12 s | |
  WebGPU 없는 PC에서는 느리므로 진행률·취소가 필수이고, 큰 그림은 '선명하게(빠름)'을 권함.
- 타일: 원본 기준 GPU 256 px / CPU 128 px, 겹침 12 px. 새 타일을 왼쪽·위 겹침에서 선형으로 섞어 덮음(따로 큰 누적 버퍼 없음). 시험: 24 px 타일과 128 px 타일 결과 PSNR > 40 dB.
- 투명도: 완전히 투명한 픽셀의 색을 주변에서 채워(블러된 미리곱/알파) 네트워크에 곧은 색으로 넣고, 알파는 고전 hq(미리곱)로 따로 키워 붙임 → 검은 테두리 없음(시험).
- 2×·3×·직접: 4×로 만든 뒤 면적 평균으로 줄임. 4×를 넘으면 나머지를 고전 hq로.

## 4. AI 방식 — 모델과 크기

| 파일(`public/models/sr/`) | 출처(Real-ESRGAN v0.2.5.0, BSD-3) | 저장 형식 | 원본 | 설치본(brotli) |
|---|---|---|---|---|
| realesr-general-x4v3.lwt | realesr-general-x4v3.pth (4,885,111 B) | f16, 가수 6비트 | 2,446,892 B | 1,775,955 B |
| realesr-general-wdn-x4v3.lwt | realesr-general-wdn-x4v3.pth (4,885,111 B) | f16, 가수 6비트 | 2,446,896 B | 1,776,307 B |
| realesr-animevideov3.lwt | realesr-animevideov3.pth (2,504,012 B) | int8, 출력 채널마다 배율 | 639,176 B | 476,465 B |

- 양자화 비교(합성 사진·일러스트·선화·화면, 깨끗/JPEG q50, f32 대비 PSNR 차이): f16 ≤ 0.001 dB, 가수 8·7비트 ≤ 0.015 dB, **가수 6비트 ≤ 0.064 dB**, int8(채널) general −0.4 dB(탈락)·anime ≤ 0.05 dB, int8(3×3마다 배율) ≤ 0.064 dB지만 더 큼. → 기준 0.1 dB 안에서 가장 작은 조합을 고름.
- 크기: 모델 합계 brotli **4,028,727 B**, 코드 증가 약 32 KB. 빌드 결과 dist 15,012,907 B(기준 10,951,450 + 허용 51,200을 4,010,257 B 넘음) — 기준 올리기는 조율 담당 결정 대기.
- 출처·sha256은 `public/models/sr/LICENSE`, `docs/legal/IP_CHECKLIST.md` 12번, THIRD_PARTY_NOTICES.md. .pth 원본은 저장소 밖에 보관한다(변환 결과 .lwt만 저장소에 있음).
- 모델은 설치본 안에 들어 있고 처음 쓸 때 읽음(내려받기 없음, OCR과 같은 방식). 없으면(개발 빌드 등) 고전 방식으로 바꾸고 알림.

## 5. 자동 판별(`core/image/sr/classify.ts`) — 무엇을 어떻게

- 내용(사진/그림·애니메이션): 256 px 사본에서 가장 흔한 16색(5비트)의 비율, 평평한 영역 비율 등. 규칙: 16색 비율 > 0.5, 또는 > 0.4이고 평평한 영역 > 0.6이면 그림.
- 손상: **JPEG 품질을 픽셀에서 거꾸로 읽음** — 8×8 격자의 저주파 DCT 계수 4개가 양자화 간격의 배수에 모이는지(위상 집중도)로 간격을 찾아 IJG 품질로 바꿈(잘린 픽셀이 있는 블록은 뺌). 잡음은 가장자리에서 먼 곳의 Laplacian(Immerkær). → 잡음 제거 강도 0.2~1(general↔wdn 가중치 보간, Real-ESRGAN의 denoise_strength와 같은 방식), JPEG q ≲ 54면 블록 먼저 줄이기.
- 픽셀 아트(`looksPixelArt`: 정확한 색 48개 이하, 세 이웃이 모두 다를 때 가운데가 양쪽 사이 값인 비율 0.45 미만, 한 변 1024 px 이하): 대화상자가 방법을 '픽셀 그대로'로 미리 고르고 이유를 보임 — AI는 픽셀 아트를 뭉갬(4×: 최근접 대비 16 dB, 고전 20 dB). 사용자가 AI를 다시 고를 수 있음.
- 대화상자 표시: '자동: 그림·애니메이션 / 잡음 중간'. 모델(자동·사진·그림)·강도·블록 줄이기를 직접 바꿀 수 있음.
- 시간: 39장 모두 15 ms 아래(대부분 2~6 ms).
- 정확도(`tests/image/sr.test.ts`, 사진 3·일러스트 2·선화 2·저장소 화면 2 × 깨끗/q80/q50/q30 + 사진 잡음 σ12, 39장): **내용 39/39, 손상 32/39**. 틀린 7장은 합성 일러스트·선화의 JPEG — 0/255로 잘린 픽셀과 가장자리뿐이라 쓸 수 있는 블록이 없어 '적음'으로 봄(그림 모델은 잡음 강도를 쓰지 않으므로 결과 차이는 블록 줄이기 여부뿐).
- 자동 vs 모델 하나 고정(원본 256 → 64로 줄이고 깨끗/JPEG q40/잡음 σ8, AI 4× 후 원본과 PSNR, 15장 평균): **자동 25.27 dB**, 사진 모델 고정 25.20, 그림 모델 고정 24.97, 고전 hq 24.93. 손상된 사진에서는 AI가 고전보다 2.5~3 dB 높고(q40: 28.6 vs 25.9), **깨끗한 합성 사진에서는 고전이 PSNR로 더 높음**(39.2 vs 32.3: GAN 모델은 잔질감을 지우고 대비를 바꿈 — 눈으로는 더 또렷하지만 PSNR은 낮음). 실제 사진(로컬 배경 사진)에서도 같은 경향(깨끗한 원본의 4× 복원: 고전 30.4 dB, AI 25.0 dB). 그래서 '선명하게(빠름)'을 함께 두고, 깨끗한 고화질 원본에는 그쪽이 원본 충실도가 높다고 안내 문구에 적음.
- 칸마다 다른 판별(사진 속 글자 등): 이번에는 전체에 하나. 타일 단위 판별 + 겹침 섞기는 다음 후보(같은 타일 구조로 가능, 모델 두 개를 GPU에 함께 올려야 함).

## 6. 오메 전용 모델(재학습) — 나중 결정용 메모(이번 작업에서는 하지 않음)

- 목표 후보: (a) 사진·화면·문서 스캔을 한 모델로(지금은 두 모델 + 보간), (b) 증류로 conv 32 → 12~16층(속도 2배, 크기 절반), (c) PSNR 쪽 손실 비중을 높인 '충실' 판(깨끗한 원본에서 고전보다 나쁘지 않게).
- 데이터: 라이선스가 분명한 고화질 사진·그림(DIV2K는 연구용 조건이라 상용 배포 모델의 학습 데이터로 쓰려면 검토 필요; CC0/자체 촬영·오메 화면 캡처·자체 제작 일러스트가 안전), 열화 합성(블러·잡음·JPEG·리사이즈)은 Real-ESRGAN 방식으로 코드로 생성.
- 계산: SRVGGNetCompact 크기는 GPU 1장(24 GB급)으로 증류 1~2일, 처음부터 GAN 학습 3~5일 정도(공개 보고 규모 기준 추정).
- 라이선스: 증류의 교사로 Real-ESRGAN(BSD-3)을 쓰는 것은 BSD 조건(표기)만으로 가능. 학습 데이터 라이선스가 실제 위험 — 변호사 검토 목록(IP_CHECKLIST 12번)에 둠.

## 7. 권고

AI(Real-ESRGAN 소형, 자동 판별)를 기본으로 두고 고전 방식을 빠른 대안·미리보기·한도 밖 처리로 유지. 다음 단계: WebGPU f16 연산, 칸마다 판별, 설치본 기준 조정(약 +4.0 MB) 결정.
